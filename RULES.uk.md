## 1. Гілки та куди пушити
- **Кожен учасник працює у власній гілці** з назвою:  
  `pdfx-support-<ваша-роль>` (наприклад: `pdfx-support-qa`).
- **Щотижневі результати** (готова робота за тиждень) пушаться **лише** у спільну інтеграційну гілку **`pdfx-support`**.
- **`main` зарезервований** для синхронізації з upstream (батьківським) репозиторієм. Не пуште туди фічі.

## 2. Чого НЕ робити (професійне попередження)
- **Не виконувати `git add .` і не пушити все підряд.** Це раніше призводило до шуму й випадкового додавання нерелевантних файлів.  
  - Нестейджені та нерелевантні файли **не повинні** потрапляти в щотижневі пуші.  
  - Якщо випадково застейджили чужі файли — **відстейджіть** їх перед комітом (команди нижче).
- **Не комітьте секрети, великі бінарні файли або згенеровані артефакти.** Використовуйте `.gitignore` або `.git/info/exclude`.

## 3. Правила повідомлень комітів (обов'язково)
- **Мова:** тільки англійська.
- **Формат:** починати з **великим літерою дієслова**, що описує дію. Перше слово має бути дієсловом: `Add`, `Fix`, `Update`, `Remove`, `Refactor`, `Test`, `Chore`.  
  - **Структура:**  `Verb short description`  
  - **Приклади:**  
    - `Add PageBoxes support for add_page`  
    - `Fix font embedding check for TrueType fonts`  
    - `Update pdf.output to accept pdf_x=True`  
- **Одна логічна зміна на коміт.** Не змішуйте нерелевантні правки в одному коміті.

## 4. Робота зі стаджингом і комітами (рекомендовані команди)
- **Стаджте інтерактивно**, щоб уникнути `git add .`:
  ```bash
  git add -p            # вибрати хунки інтерактивно
  git add <file>        # додати конкретний файл(и)
  ```
- **Відстейджити або видалити випадкові файли:**
  ```bash
  git restore --staged path/to/file   # відстейджити файл
  git rm --cached path/to/file        # припинити відстеження, залишити локально
  ```
- **Змінити/запресувати історію перед пушем:**
  ```bash
  git commit --amend --no-edit
  git rebase -i HEAD~N
  ```
- **Перед пушем перевірити:**
  ```bash
  git status
  git diff --staged --name-only
  ```

## 5. Pull request та рев'ю
- **PR:** з `pdfx-support-<name>` → в `pdfx-support`. Не робіть PR прямо в `main`.
- **CI має бути зелений** (тести + лінтери + pre-commit) перед запитом на рев'ю.
- **Тримайте PR сфокусованими:** одна фіча/багфікс на PR. Великі фічі розбивайте на кілька PR.

## 6. Тести, лінтери та pre-commit
- **Запускайте тести локально** перед пушем: `pytest`.
- **Встановіть і використовуйте pre-commit hooks** (якщо налаштовано):  
  ```bash
  pip install pre-commit
  pre-commit install
  pre-commit run --all-files
  ```
- Виправляйте стилі локально; не покладайтеся на CI для автозаміни.

## 7. Файли та артефакти
- **Не комітьте згенеровані файли** (build-артефакти, `.pyc`, віртуальні середовища, великі PDF) — додайте їх у `.gitignore` або `.git/info/exclude`.
- **Якщо згенерований файл випадково закомічено**, видаліть його з індексу і закомітьте видалення:
  ```bash
  git rm --cached path/to/generated.file
  git commit -m "Chore: remove generated artifact from repo"
  ```
